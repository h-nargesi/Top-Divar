# نیازمندی‌ها (Requirements)

> این سند پیش‌نویس است و به‌تدریج کامل می‌شود.

## ۱. شرح مسئله

پیدا کردن آگهی‌های خوب در دیوار به‌صورت دستی زمان‌بر است؛ آگهی‌های باارزش سریع فروش می‌روند. نیاز به ابزاری داریم که به‌صورت خودکار و پیوسته دیوار را پایش کند و موارد منطبق را فوراً اطلاع دهد.

## ۲. قابلیت‌های اصلی (MVP)

- [ ] تعریف «جستجوهای ذخیره‌شده»: پارامترهای جستجو (شهر/دسته/قیمت/کلمات کلیدی)
- [ ] فیلترها دقیقاً با کلیدهای بومی دیوار در کانفیگ — pass-through بدون ترجمه (`docs/configuration.md`)
- [ ] فیلتر جغرافیایی با allowlist محله‌ها از تنظیمات (تطبیق نرمال‌شده روی `district_persian` — ADR-0006)
- [ ] جدول نگاشت نام محله → district ID: برداشت خودکار از جزئیات هر آگهی + ویرایش دستی با CLI (`district`) — ADR-0006
- [ ] پایش دوره‌ای (polling) با بازه قابل تنظیم
- [ ] تشخیص آگهی جدید بر اساس token + watermark زمانی (عدم ارسال مجدد موارد قبلاً دیده‌شده)
- [ ] نرمال‌سازی پارامترهای ملک (ارقام فارسی، واحدها، قیمت توافقی، سال‌ساخت→عمر، آشتی قیمت‌متری — `docs/divar-api.md` بخش ۸)
- [ ] گرفتن جزئیات آگهی جدید از `posts-v2/web/{token}` (fallback HTML) پس از پس‌فیلتر جغرافیا (ADR-0009)
- [ ] امتیازدهی قاعده‌محور روی فیلدهای search + جزئیات: قیمت، قیمت‌متری، متراژ، اتاق، عمر، طبقه، امکانات، محله، عنوان؛ نوتیف فقط برای امتیاز ≥ حداقل (`min_score`)
- [ ] درج امتیاز و شکست آن در پیام اطلاع‌رسانی
- [ ] ارسال اطلاع‌رسانی چندکاربره تلگرام با ثبت‌نام در بات: `/start` → پسورد مشترک → username یونیک → اتصال خودکار `chat_id` در دیتابیس (ADR-0010)
- [ ] مدل پخش عمومی (broadcast): همهٔ کاربران تلگرامِ ثبت‌شده و همهٔ گیرنده‌های ایمیل، همهٔ آگهی‌های ممتاز را می‌گیرند؛ جستجوها و امتیازدهی سراسری می‌مانند (ADR-0010)
- [ ] کانال ایمیل با چند گیرنده از کانفیگ (هر گیرنده یک تحویل مستقل؛ محتوای plain text با همان فیلدهای پیام تلگرام — ADR-0010)
- [ ] جدول پیگیری ارسال (`delivery`): تحویل at-least-once — ردیف per (آگهی، کانال، گیرنده)، علامت `sent` فقط بعد از موفقیت، بدون retry خودکار (ADR-0010)
- [ ] جبران تعاملی (backfill): هر تعامل کاربر ثبت‌شده → ارسال `pending`های او، قدیمی‌ترین اول، سقف ۷ روز (ADR-0010)
- [ ] ارسال مجدد از تاریخ: دستور بات با تاریخ شمسی، همهٔ ممتازهای از آن تاریخ، سقف ۳۰ روز (ADR-0010)
- [ ] محتوای پیام: عنوان — برچسب جستجو، فیلدهای ملک، امتیاز و شکست فشردهٔ آن، لینک مستقیم — قالب مصوب: `docs/configuration.md` بخش ۳
- [ ] ذخیره تاریخچه آگهی‌های دیده‌شده (شامل موارد زیر آستانه، برای کالیبراسیون)

## ۳. قابلیت‌های آتی (Backlog)

- [ ] معیار کمیابی نسبی: قیمت‌متری در برابر میانهٔ همتای غلتان (نه دلار، نه میانگین سراسری) — طراحی: `docs/deal-scoring.md`، ADR-0008؛ پیش‌نیاز `size`/`price_per_square` از جزئیات تأمین شده؛ داده از `raw_json` ذخیره‌شده
- [ ] فیلترهای هوشمند (کلمات ممنوعه، حذف آگهی‌های تجاری/اسپم — قاعده قطعی `is_dealer`)
- [ ] کانال Ntfy (interface دامنهٔ `Notifier` برای آینده باز می‌ماند — ADR-0002)
- [ ] مدیریت جستجو از داخل تلگرام (Bot Gateway کامل: افزودن/حذف جستجو، تغییر بازه — دامنهٔ MVP فقط ثبت‌نام/جبران/ارسال‌مجدد است، ADR-0010)
- [ ] هضم/پیام خلاصهٔ «دادهٔ ناقص» به کاربر اگر دادهٔ ناقص (مثل سال ساخت غایب) به آستانهٔ بحرانی رسید (`deal-scoring.md` بخش ۴.۲ و ۱۲)
- [ ] نوتیف «کاهش قیمت» بر پایهٔ لاگ رویداد تغییر قیمت (`deal-scoring.md` بخش ۴.۴ و ۱۲)

## ۴. محدودیت‌ها و ملاحظات

- **نرخ درخواست:** فاصله منطقی بین درخواست‌ها برای جلوگیری از مسدود شدن
- **قابلیت اطمینان:** تحمل خطای شبکه و تغییر ساختار صفحات/API دیوار
- **امنیت:** توکن بات تلگرام، پسورد ثبت‌نام بات و رمز SMTP فقط از `.env`
- **زبان رابط کاربری:** فارسی
- **تورم و قیمت مسکن:** آستانهٔ ثابت تومانی فقط سقف بودجه است؛ تشخیص «آگهی خاص» با مقایسهٔ نسبی همتا انجام می‌شود (`docs/deal-scoring.md`)

## ۵. سناریوهای استفاده

1. کاربر جستجوی «آپارتمان ۸۰ متری در منطقه X زیر Y تومان» را ذخیره می‌کند.
2. سیستم هر N دقیقه نتایج را بررسی می‌کند.
3. آگهی جدیدِ منطبق → امتیازدهی؛ در صورت عبور از حداقل امتیاز، پیام تلگرام با لینک مستقیم و امتیاز.
